Email/phone + password for first (online-required) login, PIN for daily offline login. See PRD Section 10.3.

`use-current-user.ts` is the single choke point every screen reads a role through, backed by `AuthProvider.tsx` (wraps `src/app/(app)/layout.tsx`), which resolves the cached session (`session.ts`) and cached user (`localUsers` in `src/lib/db.ts`) before any authenticated screen renders. `/login`, `/register`, and `/unlock` (outside the `(app)` shell) are the entry points. `assert-permission.ts` is the write-path enforcement point (the second of the three the plan calls for: UI, Dexie write path, RLS) — call it from any write function a role gate currently only guards at the screen level. `manage-staff-client.ts` talks to the `manage-staff` Edge Function for anything that needs `service_role` (creating an `auth.users` row, role changes, PIN resets) — always online-required, unlike the rest of this app's offline-first writes.
