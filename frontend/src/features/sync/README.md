# Sync

OjàPadi writes domain data to Dexie and the outbox in one transaction. `SyncCoordinator` owns scheduling and single-flight ordering; its outbox adapter sends durable mutations to the Node application API at `/api/sync/push`. The Node service authenticates the caller, checks tenant/branch/worker scope, and invokes the idempotent `sync_apply_*` Postgres RPCs with the service-role client. The service-role client is isolated to privileged context resolution and RPC execution; ordinary inventory reads use a JWT-scoped Supabase client.

Mutable entities (`product`, `customer`, `supplier`, `branch`, and `category`) carry separate mutation/entity identities and coalesce while pending. Immutable ledger events retain distinct idempotency keys. Product snapshots include the expected version, and the RPC returns the authoritative version or a deterministic conflict result. Dependent events such as opening stock wait for their branch and product mutations; durable outbox sequence numbers provide deterministic ordering.

`/api/sync/pull` is the single session pull coordinator. It returns keyset-paginated pages for branches, categories, products, suppliers, customers/credit movements, inventory projections, sales/payment metadata, purchases, and expenses. Its opaque cursor contains a server watermark and per-dataset position; `preloadSessionData()` continues until `hasMore` is false and only then records the cursor as a complete pull. Successful records are applied to Dexie while pending local mutations are protected, and durable diagnostics record partial failures. A session is not reported as fully synced when any pull failed or remains incomplete.

Server-to-device invalidation is event-driven. An authoritative backend commit publishes a minimal private Realtime Broadcast `sync_hint`; the client treats it only as a wake-up and pulls through the existing cursor endpoint. Realtime reconnect, network return, app resume, service-worker wake, local outbox writes, and the existing manual invocation all enter the same single-flight `SyncCoordinator`. The visible app keeps a two-minute reconciliation safety wake, while hidden apps have no reconciliation timer. Realtime channel failures use bounded reconnect backoff, and retry expiry uses the same coordinator with bounded exponential backoff. These safety pulls do not download the whole business; the cursor keeps the lower watermark and the server holds a fixed upper watermark for each paginated cycle. Products and branch inventory screens read Dexie reactively, so an applied pull updates an open screen without a reload.

The only interval retained inside the synchronization subsystem is the fallback Dexie lease heartbeat used to keep one tab's lock alive; it performs no network sync. The pending-approval screen has a separate account-status poll and is not part of synchronization.

Network, temporary account approval, dependency, and server-5xx failures remain retryable with bounded backoff. Validation failures and optimistic-concurrency conflicts remain visible for resolution. When account context changes from pending to verified, the sync engine probes `/api/account-context`, updates the local account cache, and resumes eligible blocked mutations automatically.

Tests cover the real Postgres sync RPCs with PGlite, Node sync authorization/error classification, and client outbox ordering/retry/conflict behavior. The old Supabase Edge `sync-push` implementation is retained only as a deployment compatibility artifact; the browser no longer calls it.
